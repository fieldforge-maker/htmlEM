줄 번호는 2026-11-05 기준(PR #11)이라 바뀔 수 있다. 함수 이름으로 찾는다.

## 1. 일시정지 단추 (⏸ 일시정지 / ▶ 계속, P 키)

**하는 일**
- 모든 화면의 `.stage-tools` 끝에 단추를 하나 붙인다. 누르면 움직임이 멈추고, 그림은 계속 다시 그린다.
- P 키로도 켜고 끈다. 한글 자판에서도 되게 `e.key` 대신 `e.code === 'KeyP'`를 쓴다.
- 단계를 옮기거나 화면을 바꾸면 저절로 다시 움직인다. 학생이 멈춘 줄 모르고 넘어가 혼동하는 것을 막기 위해서다.

**구현 (ch31의 `EM` 안)**
1. `let paused = false`와 `setPaused(p)`를 둔다. `setPaused`는 모든 `.pause-btn`의 글, `aria-pressed`, `primary` 표시를 맞춘다.
2. `loop(fn)`에서 `const dt = last && !paused ? … : 0`으로 바꾼다. 멈춘 동안은 `fn(0)`을 부른다.
3. `tween`은 시작 시각 대신 흐른 시간 `run`을 쌓는다. 멈춘 동안에는 쌓지 않는다.
4. `goStep`에 `if (!initial && paused) setPaused(false);`를 넣는다. `show`에도 같은 줄을 넣는다.
5. `boot`의 `buildRail(def);` 다음에서 단추를 만들어 `.stage-tools`에 `appendChild`한다.
6. `boot`에서 `route()`를 부르기 전에 `setPaused(false)`를 불러 단추 글을 채운다.
7. CSS: `.stage-tools .pause-btn { min-width: 6.4em; }`로 글이 바뀌어도 폭이 흔들리지 않게 한다. `.pause-btn.primary`는 강조색.

**옮길 때 주의**
- 화면 코드가 `setTimeout`으로 진행하는 곳은 멈추지 않는다. `performance.now()`를 직접 읽는 곳(불꽃 깜빡임 등)도 마찬가지다.
  - ch31: 화면 4의 `glide` 예약이 그렇다.
  - ch29: `refineTimer`(약 2426행)는 계산 다듬기용이라 움직임과 관계없다.
  - 화면마다 `setTimeout`·`performance.now()`가 진행을 정하는지 확인한다.
- ch29·ch30의 `loop`, `tween`, `goStep`, `show`, `boot`는 ch31과 같은 꼴이라 그대로 옮기면 된다.
- 2번(단추 막대를 따로 된 줄로)을 먼저 하는 것이 좋다. 단추가 하나 늘면 막대가 넓어져 그림 글자를 더 가린다.

## 2. 단추 막대를 그림 밖(위 줄)으로

**하는 일**
- `.stage-tools`가 `position: absolute`로 캔버스 오른쪽 위에 떠 있으면 그 밑의 캔버스 글자가 가려진다. 예: 화면 1의 `V_a − V_b = …`.
- 막대를 캔버스 위 따로 된 줄로 옮겨 이런 겹침을 구조적으로 없앤다. 대신 그림 높이가 약 50 px 줄어든다.

**구현 (CSS만, HTML 구조는 그대로)**
```css
.canvas-box { position: relative; min-height: 0; display: grid; grid-template-rows: auto minmax(0, 1fr); grid-template-columns: minmax(0, 1fr); }
.canvas-box > canvas { grid-row: 2; grid-column: 1; width: 100%; height: 100%; min-height: 0; display: block; touch-action: none; }
.stage-tools { grid-row: 1; grid-column: 1; padding: 10px 10px 0; display: flex; flex-wrap: wrap; justify-content: flex-end; align-items: center; gap: 6px; }
```

**옮길 때 주의**
- `.canvas-box` 안에 캔버스와 `.stage-tools` 말고 다른 겹침 요소가 있는지 먼저 본다. 있으면 `grid-row`를 정해 줘야 한다.
- ch29에는 `.canvas-box`에 `aspect-ratio`를 주는 좁은 화면 규칙(약 387행 근처)이 있다. FHD만 시험하지만 깨지지 않는지는 본다.
- 그림이 낮아지므로 아래쪽 글(전류값, 검류계 등)이 서로 붙지 않는지 화면마다 다시 본다.
- 캔버스 쪽에 "오른쪽 위 단추를 피하려고" 글을 옮겨 둔 코드가 있으면 이제 필요 없을 수 있다.

## 3. `EM.runs(…, { plate: true })`: 글자 밑 바탕판

**하는 일**
- 자기력선, × 표시, 점선이 많이 지나는 곳의 글자 밑에 무대색 둥근 판(불투명도 0.9)을 깐다. `halo`(글자 테두리)만으로는 선이 비쳐 보이는 경우에 쓴다.

**구현**
- `runs`의 선택지에 `plate = false`를 더한다. 글 전체 폭(`total`)을 잰 뒤, 테두리를 그리기 전에 `roundRect`로 판을 칠한다.
- ch31과 ch30은 이미 같은 꼴이다. ch30은 판 색을 문자열로도 줄 수 있다.

**옮길 때 주의 (ch29)**
- ch29의 `runs`(약 5306행)는 선택지가 없는 단순형이다. 주로 `EM.haloText`를 쓴다.
- 옮기려면 `haloText`에 `plate` 인자를 더하거나, ch30의 `runs`를 가져와 바꿔 쓴다.

## 4. 결과를 말하지 않는 제목 (규칙)

- 화면 제목(`<h2>`)은 학생이 예측하기 전에 보이므로 결론을 쓰지 않는다. 질문이나 상황 설명으로 쓴다.
  - 나쁜 예: "코일 양 끝의 전위차는 전류가 아니라 전류의 변화가 정한다"
  - 좋은 예: "전류가 흐르는 코일, 양 끝의 전위차는 무엇이 정할까?"
- 탭 이름도 같은 눈으로 본다. 아직 남은 것: ch29 탭 "보강과 상쇄"는 결론을 말한다.
- 단계 설명(캡션)에서 결론을 말하는 것은 괜찮다. 퀴즈를 푼 뒤 단계에서 말하면 된다.

## 5. 자기력선 그리기 (방침)

- 손으로 그린 고리 대신 실제 장의 등고선을 쓴다. 자오면에서 Ψ = 2πρA_φ의 등고선이 자기력선이다.
- ch31 RL 코일(`RLDRAW` 안의 `fieldLines()`)은 이렇게 했다.
  - 코일과 같은 크기의 유한 솔레노이드를 고리 40개로 본다.
  - `PHYS.loopFlux`를 합해 격자를 만들고, 행진 사각형으로 등고선을 딴다.
  - 코일 가운데 높이에서 0.3R, 0.6R, 0.85R을 지나는 세 선을 그린다.
  - 한 번만 계산해 두고 다시 쓴다.
- "코일 가까운 것만"은 코일 근처 영역만 그리고, 코일에서 멀어질수록 흐리게(0.2 → 0.85 세상 단위) 지운다는 뜻이다. 선을 코일 옆에 바짝 붙여 촘촘히 지나게 하라는 뜻이 아니다. 솔레노이드 바깥의 장은 약하므로 바깥 선은 퍼져서 멀리 돌아야 맞다.
- 화살촉은 선이 아직 진한 곳에 둔다. 코일 끝을 나와 퍼지는 곳과 모여 들어가는 곳이다.
- ch29의 솔레노이드·토로이드 화면에 손그림 자기력선이 있는지 옮길 때 검토한다.
